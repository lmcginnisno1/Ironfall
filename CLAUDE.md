# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Ironfall is a 2D factory-automation / economy game built on libGDX 1.14 (Java 17). Players mine ore, move it on conveyors to a central Core, smelt it, sell it for credits, and spend credits on buildings and stored resources on upgrades.

## Commands

Use the Gradle wrapper (`./gradlew` in bash, `gradlew.bat` in PowerShell):

- `./gradlew lwjgl3:run` — build and launch the desktop game (working dir is `assets/`)
- `./gradlew lwjgl3:jar` — build runnable fat JAR at `lwjgl3/build/libs/Ironfall-<projectVersion>.jar`
- `./gradlew core:compileJava` — fastest way to check that game code compiles
- `./gradlew clean`

There are no tests and no linter configured. `settings.gradle` includes the `android` module, so Gradle configuration needs an Android SDK (via `local.properties`).

Versioning: `projectVersion` in `gradle.properties` names the JAR and is written to its manifest as `Implementation-Version`, which `IronfallGame.version()` shows on the menu (`dev` when run from Gradle). The release workflow (`.github/workflows/release.yml`) runs on `v*` tags and overrides it with `-PprojectVersion=<tag without v>`.

## Modules

- `core` — all game logic, rendering, and input (package `dev.lmcginnisno1.ironfall`)
- `lwjgl3` — desktop launcher only (`Lwjgl3Launcher`)
- `android` — Android launcher only
- `assets/` — shared resources, added to the resource path by `lwjgl3`. `assets/assets.txt` is generated by the `generateAssetList` task on every build; don't edit it by hand.

## Architecture

`IronfallGame` (an `ApplicationAdapter`) owns everything and wires the subsystems together in `create()`. Subsystems get a reference to the game and read/write its public fields (`mode`, `credits`, `engine`, `buildingManager`, `placementController`, `tileX/tileY`). Frame order in `render()`: camera → tile engine → `InputController` → `SelectionManager` → `BuildingManager.update` → world-camera batch (world, selection, placement ghost) → HUD-camera batch (`OverlayRenderer`).

- **Game modes** (`game/GameMode`): `InputController` dispatches on `game.mode`. `PlacementController.update()` is called from `InputController` during `PLACING_GENERIC`, not from `IronfallGame` — calling it twice per frame double-fires rotation.
- **World**: `TileEngine` holds the 480×270 tile grid (16 px tiles, `TileType` ids) and the world camera. `WorldGenerator.generate` fills ore tiles and places the Core.
- **Buildings**: subclasses of `buildings/Building` (tile position, footprint, `cost`, `update`, `render`, `copyAt`). `BuildingManager` keeps a list plus a tile→building `HashMap` for occupancy and lookups via `getAt(x, y)`. The Core can't be removed. Deleting a building refunds its full `cost`.
- **Item flow**: buildings that take items implement `ItemAcceptor.acceptItem(item, fromX, fromY)`, where (fromX, fromY) is the sender's tile touching the receiver. Senders call `Building.pushItem(item, tx, ty)`, which works out the sender tile. Receivers use it to filter by side: a conveyor refuses items from the tile it points at, and a splitter only accepts from behind. A new receiving building only needs to implement `ItemAcceptor`; producers don't change.
- **Power**: buildings that make or use power implement `power/PowerBlock` (`powerProduction`, `powerDemand`, `setPowerGrid`). `PowerSystem` (owned by `BuildingManager`) groups them into `PowerGrid`s: touching power blocks connect, and a `PowerNode` links every power block within `Balance.POWER_NODE_RANGE`. Grids are rebuilt only when buildings are placed/removed (`markDirty`); totals are recomputed at the start of every `BuildingManager.update`, so consumers read `grid.satisfaction()` (0..1) and scale their speed by it. Batteries implement `PowerStorage`: each frame `PowerSystem` charges them with the grid's surplus energy and drains them to cover a shortfall (both split in proportion to free space / charge), and that is folded into `satisfaction`. `CombustionGenerator` only burns coal while `grid.wantsPower()` (demand, or a battery not full). Rates are per second; battery charge is in power units.
- **Building hooks**: override `requiresOre()` for miners (placement checks for a single ore type), and `infoLines()` to get a status panel when the building is selected (first line is the title). Senders with no fixed output side can use `pushItemToAnyNeighbour`.
- **Direction/rotation**: buildings with direction use `Conveyor.Direction` (`UP, DOWN, LEFT, RIGHT`). That enum order is not a rotation order; Q/E rotation uses `PlacementController.ROTATION_ORDER` (clockwise from UP).
- **Build menu**: sidebar entries are `BuildEntry`s (name, icon, cost, factory) listed per `BuildCategory` in the `OverlayRenderer` constructor. The factory makes a prototype at (0,0); placement calls `copyAt(x, y)`. A new building needs an entry there.
- **Balance**: every tunable number (costs, rates, sell prices, buffers, upgrade costs/caps) is in `game/Balance.java`. Don't hardcode values elsewhere; buildings expose `COST = Balance.X` constants. `game/Upgrades` holds upgrade levels (paid from Core-stored resources) and computes multipliers that buildings read through `world.getUpgrades()`.
- **World seed**: `WorldGenerator.generate(engine, buildings, seed)` uses only the seeded `Random`; never use `Math.random()` there. `IronfallGame.startNewWorld(seed)` resets and regenerates.
- **Saving**: `save/SaveManager` reads and writes one gzipped binary save (`~/.ironfall/world.sav` on desktop). When testing, launch with `-Dironfall.saveDir=<scratch folder>` so the player's real save is never touched. The layout is documented at the top of that class; bump `SaveManager.VERSION` when it changes and keep reading older versions. The full tile grid is saved, not just the seed, so worldgen changes don't break old saves. Each building is saved as its `BuildingType` id, position, `facing()`, and a length-prefixed block from `writeState`/`readState`. A new building needs a `BuildingType` entry (never rename existing ids), a `type()` override, and `writeState`/`readState` for any runtime state. Autosave runs every 2 minutes and in `pause()` (window close); F5 saves and F9 reloads. Nothing is saved while `worldReady` is false (main menu before a world is loaded), so the empty startup world can't overwrite a save.
- **Menus**: `ui/MenuScreen` draws the main menu (startup) and the pause menu (Esc in NORMAL mode) in HUD space. While a menu is open, `IronfallGame.render()` skips all world updates and input; the pause menu draws over the frozen world. Menu actions call `IronfallGame.continueGame/newGame/returnToMainMenu`.
- **Assets**: `tiles/Assets` loads every sprite as a static `TextureRegion` with Nearest filtering and tracks textures for `dispose()`. Paths are relative to `assets/` (e.g. `buildings/splitter/splitter_up.png`).
- **Rendering**: `WorldRenderer` draws tiles, buildings, and items on belts. `OverlayRenderer` draws the HUD (credits, sidebar, market/upgrade panels) and also does UI hit-testing (`hitTest` / `handleUIAction`) for `InputController`. Use `TextUtil.drawOutlined` for HUD text.
